## 2. Google Cloud Console Configuration

To support Google Sign-In with Expo SDK 52+ without deprecated auth proxies, you need **two OAuth 2.0 Client IDs** in the same Google Cloud project:

### Step 2.1: Create/Select Google Cloud Project
1. Go to [Google Cloud Console](https://console.cloud.google.com/).
2. Select your project or click **New Project** (e.g. `RideColab`).
3. Navigate to **APIs & Services** → **OAuth consent screen**:
   - User Type: **External**
   - App Name: `RideColab`
   - User support email: your email
   - Developer contact email: your email
   - Scopes: `openid`, `.../auth/userinfo.email`, `.../auth/userinfo.profile`
   - Test users: add your own Gmail address for testing while in development mode.

### Step 2.2: Create the Android OAuth Client ID
1. Navigate to **APIs & Services** → **Credentials**.
2. Click **+ CREATE CREDENTIALS** → **OAuth client ID**.
3. Application type: **Android**.
4. Name: `RideColab Android Client`.
5. Package name: `dev.ridecolab.app`.
6. SHA-1 certificate fingerprint:
   ```
   D2:99:41:9C:9A:22:42:5E:0B:2F:81:90:48:A1:EF:9B:44:89:21:CE
   ```
7. Click **Create** and copy the generated client ID:
   - Format: `<ANDROID_CLIENT_ID>.apps.googleusercontent.com`

### Step 2.3: Create the Web OAuth Client ID (for Server Token Verification)
1. In **APIs & Services** → **Credentials**, click **+ CREATE CREDENTIALS** → **OAuth client ID**.
2. Application type: **Web application**.
3. Name: `RideColab Web / Backend Client`.
4. Authorized redirect URIs:
   - For server web OAuth: `http://localhost:4000/api/v1/auth/google/callback`
   - (Optional production domain when deployed)
5. Click **Create** and copy both:
   - **Client ID**: `<WEB_CLIENT_ID>.apps.googleusercontent.com`
   - **Client Secret**: `<WEB_CLIENT_SECRET>`

## 4. Re-enabling Google Sign-In in Client Code

When you are ready to rebuild the native Android app, restore native auth session handling in `client/app/login.tsx`:

### 4.1. Install / Ensure Native Dependencies
```bash
cd client
npx expo install expo-auth-session expo-web-browser expo-crypto
```

### 4.2. Update `client/app/login.tsx`
Add back the `expo-auth-session/providers/google` and `expo-web-browser` imports:

```tsx
import * as WebBrowser from 'expo-web-browser';
import * as Google from 'expo-auth-session/providers/google';
import { env } from '@/constants/env';

// Complete auth session if redirected back to web browser
WebBrowser.maybeCompleteAuthSession();
```

Inside `LoginScreen`:
```tsx
const [request, response, promptAsync] = Google.useIdTokenAuthRequest({
  clientId: env.GOOGLE_CLIENT_ID,
  androidClientId: env.GOOGLE_ANDROID_CLIENT_ID,
});

React.useEffect(() => {
  if (response?.type === 'success') {
    const { id_token } = response.params;
    if (id_token) {
      handleGoogleTokenExchange(id_token);
    }
  }
}, [response]);

const handleGoogleTokenExchange = async (idToken: string) => {
  setLoading(true);
  try {
    const data = await authApi.googleIdToken(idToken);
    setTokens(data.access_token, data.refresh_token);
    setUser(data.user);
  } catch (err: unknown) {
    const msg = err instanceof Error ? err.message : 'Google sign-in failed';
    Alert.alert('Sign in failed', msg);
  } finally {
    setLoading(false);
  }
};
```

On the button click handler:
```tsx
const handleGoogleSignIn = () => {
  if (Platform.OS === 'web') {
    Alert.alert('Mobile App Only', 'Google sign-in is enabled on the mobile app.');
    return;
  }
  if (!env.GOOGLE_ANDROID_CLIENT_ID) {
    Alert.alert('Configuration Missing', 'EXPO_PUBLIC_GOOGLE_ANDROID_CLIENT_ID is not configured in client/.env.');
    return;
  }
  promptAsync();
};
```

## 5. Build and Test in EAS Dev Client

Native modules (`expo-web-browser`, `expo-crypto`) cannot be loaded dynamically by Hermes if they were not linked into the installed APK binary.

1. **Trigger a new EAS Dev Build**:
   ```bash
   cd client
   eas build --profile development --platform android
   ```
2. **Download & Install the new APK** on your Android device (replacing the previous build).
3. **Start the dev server**:
   ```bash
   cd client
   npx expo start --dev-client
   ```
4. **Test**:
   - Tap **Continue with Google**.
   - The native Google OAuth consent sheet will pop up.
   - Choose your Google account.
   - The app sends `id_token` to `POST /api/v1/auth/google/id-token` (already implemented on backend).
   - Your tokens are stored in SecureStore and you are logged into RideColab!

## 6. Architecture & Backend Notes

- **Backend Endpoint**: `POST /api/v1/auth/google/id-token`
  - Already implemented in `server/src/routes/auth.ts`.
  - Verifies the Google ID token directly with Google (`https://oauth2.googleapis.com/tokeninfo`).
  - Verifies the token `aud` against `GOOGLE_CLIENT_ID`.
  - Automatically creates a new user or links to an existing user via `upsertGoogleUser()`.
  - Issues RideColab JWT access and refresh token pair.
  - Returns `{ success: true, data: { user, access_token, refresh_token } }`.

## 7. Troubleshooting Common Issues

| Issue | Cause | Fix |
|---|---|---|
| `Cannot find native module 'ExpoWebBrowser'` | The installed dev build APK was built without `expo-web-browser`. | Rebuild the APK using `eas build --profile development --platform android`. |
| `Error 400: redirect_uri_mismatch` | Google Web Client redirect URI does not match or auth proxy was used. | Use native Android Client ID (`GOOGLE_ANDROID_CLIENT_ID`) with your SHA-1. In SDK 52+, do not use `auth.expo.io` proxy. |
| `Token audience mismatch` | The `aud` claim in the Google ID token doesn't match the server's `GOOGLE_CLIENT_ID`. | Ensure `EXPO_PUBLIC_GOOGLE_CLIENT_ID` in `client/.env` matches `GOOGLE_CLIENT_ID` in `server/.env`. |
| `Cross-Origin-Opener-Policy would block...` | Testing OAuth popup in web browser on localhost. | Google Sign-In is intended for the Android native build. On web, Helmet COOP headers block window messaging. |
